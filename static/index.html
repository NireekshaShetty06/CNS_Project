How Website Guard works.

A rule-based prototype for preliminary website screening.

Input → URL features → TLS inspection → Weighted score → Result

The scanner validates the scheme and hostname, resolves the destination, and rejects private or reserved addresses. It connects directly to the validated public address, with the hostname supplied as TLS SNI.

Certificate verification

The system trust store verifies the certificate chain, validity and hostname. On success, the issuer, subject, DNS names, validity dates and negotiated TLS version are shown. On verification failure, we show the verifier error; unavailable fields remain unknown. HTTP submissions do not trigger TLS inspection.

Risk scoring

HTTP +25; IP hostname +25; URL credentials +30; long URL +10 or +15; long hostname +10; deep hostname +15; repeated hyphens +10; punycode +10; heavy encoding +10; identity-related hostname words +10; invalid TLS +40; unavailable TLS +10; near expiry +5. Total is capped at 100.

0–24: likely legitimate; 25–59: suspicious; 60–100: high risk. Incomplete network verification is always at least suspicious. The score is not a probability. Weights are heuristic and require dataset validation.

Scope and limitations

No reputation feed, malware scan, page-content analysis, redirect traversal, brand ownership check or machine-learning model is used. Subdomain depth is approximate and does not use the public suffix list. Newly issued valid certificates may belong to phishing sites. Network errors may affect legitimate sites.
